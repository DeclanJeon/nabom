# NABOM Living Character Growth Visual System v1.0

## 1. 목적

나봄의 캐릭터를 사용자를 판정하거나 게임화하는 장치가 아니라, 기록이 쌓일수록 **같은 사람이 조금씩 달라지는 모습을 보여주는 시각적 동반자**로 설계한다.

이 문서는 다음을 하나의 기준으로 정의한다.

- 10가지 일상어 성장 방식
- 각 성장 방식의 남성·여성 시각 변형
- 기록 누적에 따른 10단계 외형 변화
- 아키타입별 상징·소품·환경의 변화
- PNG 원본과 GIF 스프라이트 생성 파이프라인
- 프리렌더 카탈로그와 서버 부하 제어
- 사용자 노출 문구·개인정보·품질 기준

### 1.1 핵심 문장

> 사용자를 새로 만들어내는 것이 아니라, 기록 속에서 드러난 변화를 같은 캐릭터에 누적한다.

## 2. 제품 원칙

### 2.1 사용자에게는 일상어만 노출한다

사용자 화면, 캐릭터 이름, 성장 설명, 소품 설명에는 명리의 원어·한자·도식·판정 용어를 노출하지 않는다.

사용자에게 노출 가능한 예:

- 길을 여는 사람
- 이어주는 사람
- 밝히는 사람
- 온기를 나누는 사람
- 자리를 지키는 사람
- 가꾸는 사람
- 기준을 세우는 사람
- 다듬는 사람
- 흐름을 읽는 사람
- 깊이 비추는 사람

내부 계산 기준은 엔진의 결과를 사용하되, 프론트엔드와 이미지 프롬프트의 public contract에는 raw engine terminology를 전달하지 않는다.

### 2.2 캐릭터는 운명·판정·보상 시스템이 아니다

금지 표현:

- 운명, 숙명, 정해진 성격
- 레벨업, 전직, 능력치, 승급
- 강하다/약하다의 결정적 판정
- 캐릭터를 근거로 한 선택 강요

권장 표현:

- 지금 기록에서 자주 보이는 모습
- 기록이 쌓이며 달라지는 모습
- 요즘의 나를 닮은 캐릭터
- 아직 정해지지 않은 성장 방향

### 2.3 성별은 성격을 결정하지 않는다

남성·여성은 동일한 성장 방식과 상징을 서로 다른 시각 언어로 표현하는 변형이다.

성별에 따라 달라질 수 있는 요소:

- 헤어스타일
- 의상 재단
- 얼굴 인상
- 액세서리 비율

성별에 따라 달라지면 안 되는 요소:

- 성장 방식
- 단계별 상징
- 색채 체계
- 소품의 의미
- 단계 상승 조건
- 사용자에 대한 문장

## 3. 캐릭터 매트릭스

### 3.1 차원

```text
성장 방식 10개 × 성별 2개 × 성장 단계 10개
= 200개 PNG 원본
= 200개 GIF 파생물
= 총 400개 정적 자산
```

위 200개는 캐릭터의 **기본 성장 모습**이다. 실제 화면은 여기에 최근 기록의
현재 상태를 반영한다.

```text
기본 성장 단계 + 현재 상태
  ├─ rising      성장·확장
  ├─ steady      안정·유지
  ├─ strained    지침·수축
  └─ recovering  회복·재정비
```

현재 상태는 단일 기록이나 기분값 하나로 결정하지 않는다. 최근 14~28일의
활성 일일 기록을 기본 입력으로 사용하고, 정규화된 Evidence·회고 신호가
추가되면 보조 입력으로 사용한다. 원문 Journal은 상태 계산기에 직접
전달하지 않고 정규화된 신호만 전달한다.

논리 키:

```text
{growth_style_code}_{gender}_{stage_index}_{condition_state}
```

예:

```text
pathfinder_male_01_steady
pathfinder_female_01_steady
pathfinder_male_10_rising
pathfinder_female_10_recovering
```

`growth_style_code`는 내부 식별자다. 사용자에게는 항상 `display_name`을 사용한다.
`condition_state`도 사용자에게는 내부 상태명이 아니라 일상어 설명으로 번역한다.

초기 카탈로그는 200개 기본 자산으로 시작한다. 현재 상태별 변형까지 모두
프리렌더할 경우 최대 800 PNG + 800 GIF가 된다. 이 확장은 기본 자산 QA 후
단계적으로 수행한다.

### 3.2 성장 방식 목록

| 내부 코드 | 사용자 표시명 | 핵심 정서 | 색채 방향 |
|---|---|---|---|
| `pathfinder` | 길을 여는 사람 | 시작, 탐색, 개척 | 세이지·잎차·아이보리 |
| `weaver` | 이어주는 사람 | 조율, 관계, 연결 | 숲빛·보랏빛·베이지 |
| `brightener` | 밝히는 사람 | 표현, 활기, 확산 | 테라코타·살구·크림 |
| `lighter` | 온기를 나누는 사람 | 섬세함, 배려, 온기 | 촛불 금빛·블러시·크림 |
| `steadier` | 자리를 지키는 사람 | 안정, 돌봄, 지속 | 흙빛·오트밀·부드러운 갈색 |
| `gardener` | 가꾸는 사람 | 세심함, 양육, 정성 | 이끼·흙·허브 그린 |
| `decider` | 기준을 세우는 사람 | 명확함, 구조, 선택 | 차분한 금빛·돌 회색 |
| `polisher` | 다듬는 사람 | 정제, 완성도, 섬세함 | 은빛·진주·차가운 흰색 |
| `observer` | 흐름을 읽는 사람 | 관찰, 깊이, 흐름 | 안개빛·슬레이트 블루 |
| `seer` | 깊이 비추는 사람 | 고요함, 통찰, 내면 | 네이비·은빛·밤 안개 |

## 4. 성장 단계

### 4.1 단계 계산

단계는 기록 누적일수로 결정한다. 생성 호출이나 사용자의 결제·보상과 연결하지 않는다.

| 내부 단계 | 기준 기록일수 | 사용자 해석 |
|---:|---:|---|
| 1 | 0일 | 기록을 시작한 모습 |
| 2 | 7일 | 작은 흐름이 생긴 모습 |
| 3 | 14일 | 반복이 보이기 시작한 모습 |
| 4 | 21일 | 자기 리듬을 알아가는 모습 |
| 5 | 28일 | 기록을 통해 방향을 확인하는 모습 |
| 6 | 35일 | 자기 방식을 다듬는 모습 |
| 7 | 42일 | 주변에도 영향을 주는 모습 |
| 8 | 49일 | 자기 언어가 선명해지는 모습 |
| 9 | 56일 | 쌓인 경험을 활용하는 모습 |
| 10 | 63일 이상 | 지금의 나를 편안히 드러내는 모습 |

```python
STAGE_DAYS = [0, 7, 14, 21, 28, 35, 42, 49, 56, 63]
```

이 숫자는 초기 기준값이다. 실제 운영에서 기록 밀도와 사용자 피로도를 검증한 뒤 조정할 수 있으나, 조정 시 기존 사용자에게 단계가 갑자기 후퇴하지 않도록 migration policy를 둔다.

### 4.1.1 현재 상태 판정 기준

현재 상태 계산은 최근 14개 관찰값을 사용한다. 일일 기록 하나의 점수는
mood·energy·satisfaction 평균으로 정규화한다.

| 조건 | 상태 |
|---|---|
| 유효 관찰 3개 미만 | `steady`, 낮은 신뢰도 |
| 최근 7개 평균 ≤ 2.5 | `strained` |
| 이전 구간 평균 ≤ 2.8, 최근 7개 평균 ≥ 3.4, 차이 ≥ 0.35 | `recovering` |
| 최근 7개 평균 ≥ 3.8, 이전 구간 대비 상승 ≥ 0.30 | `rising` |
| 그 외 | `steady` |

상태 전환에는 다음 안정화 규칙을 적용한다.

- 3개 미만 관찰에서는 기존 상태를 바꾸지 않는다.
- 새 후보 상태가 한 관찰 구간에서만 나타나면 기존 상태를 유지한다.
- 7일 관찰 창에서 같은 후보가 유지될 때만 상태를 확정한다.
- `strained`에서 `steady` 또는 `rising`으로 바로 점프하지 않고 `recovering`을 거친다.
- 상태 변경 이력은 ProfileVersion 또는 character state history에 기록한다.

### 4.2 단계 표현 원칙

단계가 올라갈수록 다음 네 요소가 조금씩 변화한다.

1. **상징**: 단순한 물건에서 완성된 상징으로
2. **자세**: 조심스러운 자세에서 편안하고 열린 자세로
3. **의상**: 기본형에서 개인적인 디테일이 있는 형태로
4. **환경과 빛**: 작은 주변 공간에서 더 넓고 따뜻한 공간으로

단계가 올라가도 다음은 유지한다.

- 얼굴의 핵심 인상
- 헤어와 체형의 정체성
- 핵심 색채
- 아키타입의 중심 소품 언어
- 비전투적이고 일상적인 분위기

### 4.3 성장과 퇴화는 별도 축이다

`stage_index`는 기록을 누적한 여정의 위치이고, `condition_state`는 최근
상태다. 따라서 다음 조합이 모두 가능해야 한다.

| 누적 단계 | 현재 상태 | 시각 표현 |
|---:|---|---|
| 3 | rising | 시선이 올라가고, 자세가 열리고, 새 소품이 정돈됨 |
| 7 | steady | 익숙한 소품을 편안하게 사용하고 중심이 안정됨 |
| 7 | strained | 어깨가 좁아지고, 시선이 낮아지고, 옷차림이 단순해짐 |
| 7 | recovering | 따뜻한 색과 회복 소품이 돌아오지만 과장된 자신감은 없음 |

따라서 “10단계에 도달했으니 항상 더 화려하고 강해진다”는 규칙을 사용하지
않는다. 높은 단계에서도 지칠 수 있고, 낮은 단계에서도 좋은 회복이 시작될
수 있다.

#### 4.3.1 상태별 시각 규칙

| 상태 | 포즈 | 표정·시선 | 패션·헤어 | 빛·소품 |
|---|---|---|---|---|
| `rising` | 가슴과 시선이 열림, 동작이 앞으로 향함 | 눈빛이 또렷하고 표정이 살아 있음 | 새 디테일·정돈된 레이어 추가 | 핵심 상징이 선명하고 주변 빛이 넓어짐 |
| `steady` | 중심이 안정되고 자연스러움 | 편안한 미소 또는 집중 | 현재 단계의 기본 패션 유지 | 소품을 편안하게 사용하는 모습 |
| `strained` | 어깨가 내려가고 동작이 작아짐 | 시선이 낮거나 생각이 많음 | 장식 축소, 머리와 옷이 조금 흐트러짐 | 빛을 낮추고 핵심 소품을 가까이 둠 |
| `recovering` | 몸을 다시 세우는 중간 자세 | 조심스럽지만 따뜻한 표정 | 익숙한 옷에 작은 정돈·회복 디테일 | 작은 불빛·찻잔·물·휴식 소품 등 |

이 변화는 성별 고정관념을 사용하지 않는다. 남성·여성 모두 같은 상태
규칙을 공유하며, 헤어·의상·표정은 각 캐릭터의 디자인 언어 안에서 변한다.

#### 4.3.2 변화의 안정성

- 매 요청마다 랜덤 포즈·헤어·패션을 뽑지 않는다.
- `profile_id + profile_version + stage + condition_state`를 `appearance_seed`로 사용한다.
- `appearance_seed`는 내부 감사·재생성용이며 public response에 노출하지 않는다.
- 상태가 1회 흔들렸다고 즉시 외형을 바꾸지 않는다.
- 최소 관찰 창과 hysteresis를 두어 7일 동안 안정적으로 유지한다.
- 상태가 바뀌어도 얼굴 핵심 인상·체형·색채·대표 소품은 보존한다.

## 5. 단계별 상징 성장 설계

각 행은 독립적인 시각 서사를 가져야 한다. 단순히 같은 캐릭터의 크기·밝기만 바꾸지 않는다.

| 성장 방식 | 1단계 | 3단계 | 5단계 | 7단계 | 10단계 |
|---|---|---|---|---|---|
| 길을 여는 사람 | 새싹 화분 | 갈림길의 가지 | 첫 정상의 깃발 | 나침반과 배낭 | 지평선을 가리키는 깃발과 나침반 |
| 이어주는 사람 | 실타래 | 작은 다리 | 사람을 잇는 그물 | 수놓은 천 | 모두를 잇는 태피스트리 |
| 밝히는 사람 | 불씨 | 등불 | 벽난로 | 등대 | 무대 위의 따뜻한 빛 |
| 온기를 나누는 사람 | 촛불 | 등잔 | 함께 나누는 등불 | 달빛 아래 찻잔 | 여러 개의 작은 별빛 |
| 자리를 지키는 사람 | 씨앗 | 작은 정원 | 농장의 문 | 오래된 나무 | 대지를 감싸는 모습 |
| 가꾸는 사람 | 흙 한 줌 | 화단 | 분재 | 온실과 허브 | 오래된 정원 |
| 기준을 세우는 사람 | 연필 | 가위와 선 | 설계도 | 나침반 | 방향타 |
| 다듬는 사람 | 숫돌 | 조각칼 | 다듬는 보석 | 정밀 도구 | 빛나는 보석 |
| 흐름을 읽는 사람 | 물방울 | 강물 | 깊은 바다 | 별빛 | 밤하늘 전체 |
| 깊이 비추는 사람 | 고요한 연못 | 이슬 | 깊은 샘 | 별들의 지도 | 조용히 빛나는 등 |

1·3·5·7·10단계는 콘셉트 검토용 대표 지점이며, 실제 카탈로그는 1~10단계 전체를 생성한다.

## 6. Asset Pipeline

### 6.1 생성 원칙

사용자별로 Codex 이미지 생성을 동기 호출하지 않는다.

```text
콘셉트 프롬프트
   ↓ 1회 배치 생성
PNG 원본 200개
   ↓ 자동 합성
GIF 200개
   ↓ 정적 저장소/CDN
모든 사용자 재사용
```

카탈로그가 완성되면 사용자 요청은 파일 선택과 URL 반환만 수행한다.

현재 상태 변형은 다음 두 단계로 운영한다.

1. **기본 카탈로그**: 200개 기본 자산을 먼저 완성한다.
2. **상태 카탈로그**: 상태별 변형을 async worker로 생성하고 캐시한다.

상태 카탈로그의 키는 사용자 ID가 아니라 조합 키다. 따라서 같은 상태를
사용하는 사용자가 늘어나도 생성 수는 조합 수 이상으로 증가하지 않는다.
장기적으로는 800 PNG + 800 GIF 전체를 프리렌더해 요청 부하를 0으로 만든다.

### 6.2 카탈로그 우선과 폴백

```text
catalog/{growth_style_code}_{gender}_{stage}.png 존재?
  ├─ yes → catalog PNG/GIF URL 반환, 생성 호출 없음
  └─ no  → 상태 카탈로그 또는 기존 개별 PNG 생성 경로를 비동기 사용
```

폴백은 카탈로그 완성 전 서비스 중단을 막기 위한 transitional path다. 카탈로그가 존재하면 항상 카탈로그가 우선한다.

### 6.3 GIF

GIF는 PNG에서 파생한다.

- 8프레임
- 투명 배경 유지
- 위아래 bob
- 미세한 호흡 스케일
- 미세한 기울임
- 무한 반복
- 이미지 모델에 프레임별 생성 요청을 하지 않음

GIF 파생 실패 시 PNG를 사용한다. GIF 실패가 프로필 생성 실패로 이어지면 안 된다.

### 6.4 저장 경로

```text
frontend/public/characters/stage/
  pathfinder_male_01.png
  pathfinder_male_01.gif
  pathfinder_female_01.png
  pathfinder_female_01.gif
  brightener_male_05_recovering.png
  brightener_male_05_recovering.gif
  ...
```

프리렌더 작업은 중단·재개 가능해야 한다. 같은 키의 파일이 유효하면 재생성하지 않는다.

### 6.5 Asset Manifest와 배포

각 배치에는 다음 manifest를 함께 생성한다.

```json
{
  "manifest_version": "2026-08-14.1",
  "assets": [
    {
      "key": "brightener_male_05",
      "png": "brightener_male_05.png",
      "gif": "brightener_male_05.gif",
      "sha256_png": "…",
      "sha256_gif": "…",
      "prompt_version": "character-prompt-2",
      "qa_status": "approved"
    }
  ]
}
```

- 임시 디렉터리에서 생성·검증 후 manifest와 함께 atomic rename한다.
- `qa_status != approved`인 자산은 catalog resolver가 선택하지 않는다.
- 새 manifest 배포 전 이전 manifest를 보존한다.
- 잘못된 자산 발견 시 manifest pointer를 이전 버전으로 되돌린다.
- CDN cache key에는 manifest version을 포함한다.

## 7. Runtime Contract

### 7.1 CharacterProfile 필드

```json
{
  "character_profile_id": "cp_xxxxxxxx",
  "profile_version_id": "pv_xxxxxxxx",
  "catalog_key": "brightener_male_05",
  "state_catalog_key": "brightener_male_05_recovering",
  "stage": 5,
  "stage_name": "벽난로",
  "condition_state": "recovering",
  "condition_label": "다시 힘을 고르는 중",
  "image_url": "/characters/stage/brightener_male_05.png",
  "image_gif_url": "/characters/stage/brightener_male_05_recovering.gif",
  "image_status": "catalog",
  "user_editable": true,
  "status": "active"
}
```

`visual_key`는 저장소 내부의 레거시 식별자로만 보존한다. public response에는
포함하지 않는다. 실제 자산 선택은 `state_catalog_key`가 있으면 우선하고,
없으면 `catalog_key`를 사용한다.

### 7.2 변경 시점

- 초기 프로필 생성: 기록 0일, 1단계
- 기록 누적: 다음 단계 기준을 충족하면 다음 조회/프로필 갱신 시 반영
- ProfileVersion refresh: 해당 시점의 기록일수를 저장하고 캐릭터 단계에 반영
- 최근 Evidence: `condition_state`를 rising/steady/strained/recovering 중 하나로 갱신
- 기록 삭제: 단계가 자동으로 후퇴하지 않는다. 이미 관찰된 여정의 안정성을 유지한다.
- 최근 상태는 후퇴할 수 있다. 이는 누적 단계의 삭제가 아니라 현재 컨디션의 변화다.
- 계정 삭제: 캐릭터 연결정보와 개인 프로필을 함께 삭제한다. 공유 카탈로그 자산은 삭제하지 않는다.

## 8. 생성·운영 비용

### 8.1 생성 수

| 항목 | 수량 |
|---|---:|
| 성장 방식 | 10 |
| 성별 변형 | 2 |
| 성장 단계 | 10 |
| PNG 원본 | 200 |
| GIF 파생 | 200 |
| 총 정적 파일 | 400 |

이 비용은 사용자 수에 비례하지 않고 고정된다. 10만 명의 사용자가 같은 조합을 사용해도 이미지 생성은 추가로 발생하지 않는다.

상태별 완성 자산을 모두 별도 파일로 프리렌더하는 확장안:

| 항목 | 수량 |
|---|---:|
| 기본 조합 | 200 |
| 현재 상태 | 4 |
| 상태별 PNG | 800 |
| 상태별 GIF | 800 |
| 상태 카탈로그 총계 | 1,600 |

초기에는 기본 400개를 먼저 완성하고, 상태 변형은 실제 Evidence와 QA가
확인된 뒤 상태 카탈로그로 확장한다. 상태별 파일을 만들더라도 사용자 수에
비례하지 않는 고정 카탈로그라는 원칙은 유지한다.

### 8.2 운영 제한

- 이미지 생성은 web request에서 동기 실행하지 않는다.
- 배치 worker 또는 운영자 실행으로만 수행한다.
- 생성 job은 idempotency key를 갖는다.
- 실패한 자산은 retry와 실패 목록으로 관리한다.
- 기본 카탈로그 완성률을 `generated / 200`으로 관찰한다.
- 상태 카탈로그 완성률을 `generated / 800`으로 별도 관찰한다.
- GIF는 PNG 성공 후에만 생성한다.

## 9. QA 기준

### 9.1 구조 QA

- 10 성장 방식 × 2 성별 × 10 단계 파일 키가 모두 유효하다.
- 모든 단계에 상징이 정의되어 있다.
- 남성·여성 자산이 같은 성장 방식과 같은 단계의 상징을 공유한다.
- 이미지 URL이 다른 행 또는 다른 단계로 잘못 매핑되지 않는다.
- 카탈로그가 있으면 Codex 생성 호출이 발생하지 않는다.

### 9.2 콘텐츠 QA

- 명리 원어·한자·점술·운세 표현이 프롬프트, public response, alt text에 없다.
- 무기·전투·신화 동물·운명 판정 이미지가 없다.
- 단계 1과 단계 10이 같은 인물로 인식된다.
- 단계 변화가 소품·자세·빛·환경에서 확인된다.
- rising/steady/strained/recovering 상태가 포즈·표정·패션·헤어·빛에서 구별된다.
- strained 상태가 캐릭터의 정체성을 지우거나 벌·실패처럼 표현되지 않는다.
- recovering 상태가 무조건 stage 상승이나 과장된 긍정으로 표현되지 않는다.
- 같은 입력을 반복하면 같은 포즈·표정·패션 변형이 재현된다.
- 남성·여성 모두 독립적인 매력과 자연스러운 일상성을 가진다.
- 성별별 고정관념이나 성능 차이를 암시하지 않는다.

### 9.3 기술 QA

- PNG가 유효하고 투명 영역이 보존된다.
- GIF가 8프레임·무한 반복·투명 배경을 갖는다.
- GIF가 없거나 깨져도 PNG로 화면이 동작한다.
- 카탈로그 미완성 시 개별 생성 폴백이 동작한다.
- 생성 실패가 프로필 생성·로그인·기록 저장을 막지 않는다.
- 최근 상태가 바뀌어도 누적 단계와 상태가 서로 덮어쓰지 않는다.
- manifest 없는 자산·checksum 불일치 자산은 서비스 선택 대상에서 제외된다.
- 이전 manifest로 rollback했을 때 기존 URL이 정상적으로 복구된다.
- 모바일과 데스크톱에서 캐릭터 비율·용량·alt text가 정상이다.

### 9.4 수동 시각 QA

자동 테스트와 별도로 각 배치에서 다음 샘플을 사람이 확인한다. 완료 시
`manual_visual_qa.md` 체크리스트에 확인자·날짜·결과(approve/reject)를
기록하고, reject 항목은 해당 자산만 재생성한다.

**샘플 커버리지**

- 10가지 성장 방식 × 2성별 중 최소 각 1개 (20개)
- 단계 1·5·10 (성장 3지점)
- 상태 rising·steady·strained·recovering

**행 연속성 (같은 아키타입)**

- [ ] 단계 1→5→10이 같은 인물로 인식되는가 (얼굴·헤어·체형 유지)
- [ ] 단계가 올라갈수록 상징·자세·빛·환경이 자연스럽게 발전하는가
- [ ] 어떤 단계에서 갑자기 다른 사람으로 바뀌지 않는가
- [ ] 색채 체계가 같은 행 전체에서 일관적인가

**상태 구분 (같은 단계 내)**

- [ ] rising/steady/strained/recovering가 포즈·표정·패션·헤어·빛에서 구별되는가
- [ ] strained가 실패·벌·추락·우울증처럼 보이지 않고 "지침"으로 읽히는가
- [ ] recovering이 억지로 밝아지거나 가스라이팅처럼 보이지 않는가
- [ ] steady가 밋밋하지 않고 편안한 안정으로 보이는가

**남성·여성 동등성**

- [ ] 같은 성장 방식·단계에서 두 성별이 같은 상징·색채·의미를 공유하는가
- [ ] 어느 한쪽이 더 강해 보이거나 약해 보이지 않는가
- [ ] 성별 고정관념(감정 억제·보호자·요양자)을 강요하지 않는가

**기타**

- [ ] GIF가 부드럽게 움직이고 (프레임 점프 없음) 투명 배경이 유지되는가
- [ ] 모바일·데스크톱에서 깨짐 없이 렌더링되는가
- [ ] 파일명/alt text에 명리·점술·개인정보가 없는가

## 10. 보안·개인정보·권리

- 캐릭터 파일명과 URL에는 사용자 ID, 생년월일, raw chart, 계정 이메일을 포함하지 않는다.
- 사용자별 파일을 만들지 않으므로 개인 식별 정보가 정적 자산에 들어가지 않는다.
- 생성 프롬프트에는 raw engine response를 전달하지 않는다.
- 이미지 생성 공급자의 사용권·저장 정책·재사용 권한을 운영 전에 확인한다.
- 삭제된 계정의 프로필이 카탈로그 URL을 통해 복원되지 않도록 프로필 API에서 연결정보를 삭제한다.

### 10.1 이미지 생성 공급자 권리 확인 항목 (A2)

출시 전 운영 책임자가 다음을 공급자 문서·계약에서 확인한다.

- [ ] 생성 이미지의 서비스 내 재사용(사용자 노출·저장) 권한
- [ ] 생성 이미지의 변형(크롭·GIF 파생·색조·리사이즈) 허용 여부
- [ ] 장기 보관(카탈로그 정적 파일) 기간 제한 여부
- [ ] 사용자에게 전달된 이미지의 상업적 사용 범위
- [ ] 생성 결과에 대한 권리 귀속(공급자/운영자/사용자)
- [ ] 삭제 요청 시 이미지 처리 절차
- [ ] 재생성(같은 프롬프트 재호출) 정책과 비용
- [ ] 모델 학습에 생성물이 사용되는지 여부와 opt-out 절차
- [ ] 라이선스 변경 통지 절차와 현행 계약 버전 기록

## 12. 결정 사항

1. 사용자별 생성이 아니라 고정 카탈로그를 사용한다.
2. 캐릭터 정체성은 성장 방식·성별·단계 조합으로 결정한다.
3. 남성·여성은 같은 의미의 동등한 시각 변형이다.
4. 단계별 차이는 아이템·상징·자세·환경으로 표현한다.
5. GIF는 PNG에서 파생하며 이미지 모델에 프레임 생성을 반복 요청하지 않는다.
6. 사용자에게는 명리 대신 일상어만 제공한다.
7. 단계가 후퇴하지 않도록 기록 삭제는 성장 단계를 자동 감소시키지 않는다.
8. 카탈로그 미완성 기간에는 기존 개별 생성 폴백을 허용하되, 카탈로그 완성 후 정적 재사용으로 전환한다.
